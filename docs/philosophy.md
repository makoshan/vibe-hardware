# 思想：什么是 Vibe Hardware

参考：[Vibe Coding Hardware · nav.al](https://nav.al/hardware)

## 一句话

用最强模型加速生成，用最短实物闭环做验证；**人守验收，不守打字**。

## 从文章里抽的要点

1. **硬件流程里早有软件**（Excel、邮件交接），只是没当软件管：无版本、无测试。应变成可重复框架。
2. **分工**：软件侧搭架构；懂硬件的人 vibe 自己的层。
3. **软件仍需要手**：AI 会出 STEP / PCB，但买不到的集成仍要自己做。
4. **人变成 Verifier**：签后果、写测试/仿真、出事能站台。

## 对教学的约束

- 适合引用方法的仓库（如 luckiday/vibe-hardware）≠ 可直接当学员逐步教程。
- **只有真实编译、打板、打印、装配验证过的步骤**，才能写进 checklist。
